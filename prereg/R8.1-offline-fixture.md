# R8.1 — an offline fixture for the candidate contract

## What this run is for

Six questions over two SQLite databases built from `eval/cases/fixture.json`, answered by
`eval/plugins/keyword-router.mjs`, a module that does not import from this repository and lives
outside `packages/eval`. No model, no network. The run exists so that the harness's own arithmetic
has a case where the right answer is known in advance: if the score moves, the harness moved.

## Prediction

- The router answers all six cases, so the answer-rate gate passes at 100% and `metrics.answered` is 6 of 6.
- It is correct on exactly two: the two questions that count every row of the table they name, where its unfiltered count and the gold agree.
- It is wrong on the two filtered counts, because it drops the filter: three customers against a gold of two, four loans against a gold of two.
- It is wrong on the two list questions, because it projects every column where the gold projects one.
- The measured accuracy is therefore 0.3333 with a Wilson interval that contains 0.10 and 0.70, and the artefact's `metrics.correct` equals the number of cases marked correct.
- Re-running the same case file with the same plugin reproduces every case verdict exactly; only `generatedAt` differs.

## Refutation

- If the fixture scores anything other than two of six, the harness is not scoring the comparison it prints and no other number it produces may be quoted.
- If a case with an unexecutable answer is counted as unanswered rather than wrong, the answer-rate gate is measuring the wrong denominator and V29 is withdrawn.
- If the committed report cannot be regenerated from the committed artefact, the report is a second source of truth and every claim in it is unverified.

## Note

This is an instrument check, not a benchmark. It has no scientific claim about memory: it exists so
that the arithmetic between a generator, a database and a score is exercised by something that
cannot drift with a model version.
